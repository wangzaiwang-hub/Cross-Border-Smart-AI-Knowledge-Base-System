# 后端交付技术规格

## 1. 目标

使用 JDK 25、Spring Boot 4.0.7 和 Maven 多模块工程，交付商城、知识库、AI 客服、培训和统一管理后台所需的分布式后端服务，并提供可供 Vue 3 前端直接接入的稳定契约。

## 2. 工程闭环

当前版本必须形成以下闭环：

1. Maven 根工程、企业 BOM、公共模块、Gateway、认证和用户服务可构建与启动。
2. 注册登录、个人资料和地址管理闭环。
3. 商品浏览、库存锁定、订单创建、虚拟充值、模拟支付、取消与模拟履约闭环。
4. 知识上传、审核、发布、解析、全文/向量索引和版本追溯闭环。
5. AI 会话、混合检索、受控商品工具、引用回答、拒答和反馈闭环。
6. 岗位课程、文档学习、关卡测验、进度计算和统计闭环。
7. RBAC、审计、通知、限流、配置、健康检查和可观测性闭环。
8. OpenAPI、接口清单、DTO、错误码、权限码、事件、数据库和验证证据同步交付。

## 3. 模块结构

模块结构以 `docs/项目设计架构文档.md` 为准：根项目 → 副项目 → 功能聚合项目 → API/Service 子项目。所有可运行服务必须有独立 `pom.xml`、标准 Maven 目录、Dockerfile 和健康检查。

## 4. 契约规则

- 外部接口统一通过 Gateway 的 `/api/v1/**` 暴露。
- API DTO 与 Entity 分离；跨服务只依赖目标服务的 `*-api` 模块。
- ID、金额、日期时间、分页、错误响应按 `docs/development/后端接口与前端接入清单.md` 执行。
- OpenAPI 是机器可读契约，Markdown 清单是面向前端和评审的补充，两者必须一致。
- 已标记“可联调”的接口不得发生未版本化破坏性变更。

## 5. 数据与事务

- 每个服务拥有独立数据库或 Schema，禁止跨服务直接访问数据库。
- 订单、钱包和库存以数据库为事实来源。
- 钱包余额和流水位于同一本地事务；金额使用 `DECIMAL`/`BigDecimal`。
- 下单、支付、库存和消息消费必须支持幂等。
- RocketMQ 按至少一次投递设计，消费者必须去重。
- Elasticsearch 与 PGVector 是可重建派生索引。

## 6. 安全

- 密码、JWT 密钥、数据库口令、豆包 Key 只通过环境变量或 Secret 文件注入。
- 日志不得输出密码、Token、完整地址、私钥和模型 Key。
- 后端执行登录、角色、权限和数据所有权校验；不能依赖前端路由守卫。
- 上传文件必须校验扩展名、MIME、大小、访问范围和恶意内容风险。
- AI 不能直接执行 SQL、修改订单、调整余额或发布知识。

## 7. 资源受限 DEV 运行规则

- 本机使用 Temurin JDK 25.0.3 和 Maven Wrapper 构建。
- 虚拟机不依赖系统 Java/Maven，使用固定 JDK 25 基础镜像运行服务。
- core、mall、ai-apps、training 按场景切换，不要求全量常驻。
- Java 服务必须设置容器内存、JVM 堆、健康检查和日志轮转。
- 每次场景切换后执行组件健康检查、Nacos 注册检查和端到端接口测试。

## 8. 测试优先级

1. 公共响应、错误码和安全过滤器单元测试。
2. 认证、权限和资源所有权测试。
3. 钱包、订单、库存状态机与幂等测试。
4. 数据库迁移和 Testcontainers 集成测试。
5. Feign 契约和 RocketMQ 事件 Schema 测试。
6. 知识发布、索引、RAG 引用与拒答测试。
7. 培训关卡和进度服务端计算测试。
8. Gateway 端到端回归、性能、安全与部署冒烟测试。

## 9. 完成定义

模块只有同时满足以下条件才能标记完成：

- `./mvnw clean verify` 通过。
- 单元、集成和契约测试达到验收标准。
- 数据库迁移可从空库执行。
- Docker 镜像可构建，健康检查通过。
- 通过 Gateway 的成功、失败、401、403 和幂等场景验证。
- OpenAPI、接口清单、错误码、权限码、事件和开发记录已同步。
- 无真实 Secret、无未解释的测试跳过、无 P0/P1 缺陷。
