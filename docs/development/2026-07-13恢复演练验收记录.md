# 2026-07-13 恢复演练验收记录

## 演练原则

本次从虚拟机真实 MySQL 和 PGVector 执行只读导出，将备份恢复到本机一次性隔离容器。不对虚拟机原库执行写入或破坏性恢复。密码仅从本地忽略的 `.env` 注入子进程，未写入报告和 Git。

## 实测结果

| 项目 | 结果 |
|---|---|
| MySQL 全库一致性备份 | 909,250 bytes，6.43 秒 |
| MySQL 隔离恢复 | 15.14 秒，源端/恢复端均为 105 张业务表 |
| PGVector custom-format 备份 | 7,153 bytes，1.82 秒 |
| PGVector 隔离恢复 | 0.29 秒，源端/恢复端均为 3 张表 |
| 恢复库容器同时重启 | 4.71 秒内就绪，重启后表数不变 |
| 附件归档恢复 | 2 个测试文件逐文件 SHA-256 一致 |
| 通知死信重放 | `NotificationServicesIntegrationTest` 通过，覆盖死信、手工重放、再投递及不存在死信 |
| 知识索引重建 | 已增加幂等全量重建 API；`KnowledgeJobRecoveryIntegrationTest` 通过 |
| 索引版本切换 | `SearchServicesTest` 3/3 通过，覆盖新建、有数据才切换、删除上一版本 |

## RPO / RTO 结论

- 本次演练恢复点为演练开始时创建的一致性快照，实测 RPO 小于 1 分钟。
- 数据库导入加重启就绪的核心恢复时间小于 1 分钟，显著低于开发环境 RTO 4 小时和企业环境 RTO 2 小时的项目目标。
- 企业 RPO 1 小时需由服务器将 `backup-data.sh` 按小时调度，并将备份复制到异机或对象存储。本次验证了备份可恢复性，不以单机本地备份代替异地容灾。
