# 依赖、漏洞与许可证治理

## 1. 固定策略

- Java 依赖版本优先由 `ygh-dependencies` 统一管理，业务模块不得自行覆盖核心框架版本。
- 每周由 Dependabot 检查 Maven、pnpm 与 GitHub Actions 更新。
- Pull Request 与主分支构建生成 CycloneDX 1.6 SBOM，并使用 Trivy 执行漏洞、错误配置、Secret 和许可证扫描。
- HIGH/CRITICAL 且已有修复的漏洞阻断交付；未修复漏洞必须记录影响面、缓解措施、负责人和复审日期。
- Apache-2.0、MIT、BSD、ISC、EPL、CDDL、Unicode、CC0 和 Public Domain 可自动放行；LGPL 及 Classpath Exception 进入人工复核；策略外许可证阻断。

## 2. Javassist 风险处置

RocketMQ Client 5.3.1 经 `rocketmq-remoting → reflections 0.9.11` 间接引入 Javassist 3.21.0-GA。该版本年代久远，并在 JDK 25 项目中形成不必要的供应链风险。

处置决定：在企业 BOM 中将 `org.javassist:javassist` 统一提升到 Maven Central 当前 GA `3.31.0-GA`，由兼容性测试和全 Reactor 门禁验证 RocketMQ 代表类、消息生产/消费适配器及 JDK 25 链接能力。禁止业务模块降级覆盖。

## 3. 自动化命令

```powershell
.\mvnw.cmd -Prelease-sbom package -DskipTests
.\ygh-deploy\scripts\audit-sbom.ps1
.\ygh-deploy\scripts\check-staged-secrets.ps1
```

GitHub CI 额外运行 Trivy；扫描报告和 SBOM 作为构建产物保存。任何例外必须更新本文件，不能仅在 CI 中添加忽略规则。
