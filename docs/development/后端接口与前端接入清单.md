# 后端接口与前端接入清单

> 状态：持续维护  
> 目标：后端开发期间同步记录所有前端接入所需契约；接口完成、测试通过、部署可达后才能标记“可联调”。

## 1. 维护规则

每个接口必须记录以下信息：

1. 服务、模块、用途、负责人和状态。
2. HTTP 方法、Gateway 路径、服务内路径和 API 版本。
3. 是否允许匿名、所需角色、权限码和数据所有权规则。
4. Path、Query、Header、Body 参数及 Bean Validation 约束。
5. 请求 DTO、响应 DTO、分页结构、枚举和金额/时间格式。
6. 成功状态码、HTTP 错误码、业务错误码和错误示例。
7. 幂等键、限流、超时、重试和并发规则。
8. 涉及的数据库事务、缓存、消息事件、搜索索引和审计动作。
9. OpenAPI 地址、Mock 数据、自动化测试和联调证据。
10. 变更历史、兼容性影响和废弃计划。

禁止只写“接口完成”。没有测试证据、权限说明和错误码的接口仍视为未完成。

## 2. 全局协议

### 2.1 Gateway 基地址

```text
/api/v1
```

正式环境域名和 HTTPS 终止位置待部署环境确认，前端不得写死开发机或虚拟机 IP。

### 2.2 统一响应

```json
{
  "code": "SUCCESS",
  "message": "操作成功",
  "data": {},
  "traceId": "01J...",
  "timestamp": "2026-07-11T15:00:00+08:00"
}
```

### 2.3 分页响应

```json
{
  "code": "SUCCESS",
  "message": "操作成功",
  "data": {
    "records": [],
    "pageNo": 1,
    "pageSize": 20,
    "total": 0,
    "pages": 0
  },
  "traceId": "01J...",
  "timestamp": "2026-07-11T15:00:00+08:00"
}
```

分页参数统一为 `pageNo`、`pageSize`；默认 1/20，最大 `pageSize` 100。

### 2.4 通用 Header

| Header | 必需 | 用途 |
|---|---|---|
| `Authorization: Bearer <token>` | 受保护接口必需 | 访问令牌 |
| `X-Request-Id` | 建议 | 客户端请求跟踪；缺失时 Gateway 生成 |
| `Idempotency-Key` | 指定写接口必需 | 下单、充值、支付、退款等防重 |
| `Accept-Language` | 可选 | 默认 `zh-CN` |

### 2.5 数据格式

- ID：JSON 字符串，避免 JavaScript 大整数精度问题。
- 金额：字符串形式的十进制定点数，例如 `"99.80"`；币种单独使用 `CNY`。
- 时间：ISO 8601，统一携带时区，例如 `2026-07-11T15:00:00+08:00`。
- 日期：`yyyy-MM-dd`。
- 枚举：稳定英文代码，中文显示文案由接口枚举字典或前端映射提供。
- 文件上传：`multipart/form-data`，同时限制 MIME、扩展名和大小。
- 浏览器跨域来源由部署环境精确白名单控制，不接受 `*`；credentials 请求必须命中白名单。
- 普通请求体默认不超过 2 MiB；multipart 上传默认不超过 50 MiB 且必须提供 `Content-Length`。

## 5. 已冻结接口明细

## 5.1 Auth Service v1 冻结清单

运行时 OpenAPI 冻结文件：[auth-service-v1.json](../../spec/openapi/auth-service-v1.json)。开发实例直接地址为 `http://127.0.0.1:18081`；前端只能使用 Gateway 基地址，不能直连服务端口。所有成功和失败响应均使用 `code/message/data/traceId/timestamp`。

| 方法与路径 | 认证 | 成功 | 主要错误 | 当前状态 |
|---|---|---:|---|---|
| `GET /api/v1/auth/captcha` | 匿名 | 200 | 429、503 | 可联调 |
| `POST /api/v1/auth/register` | 匿名 | 201 | 400、409、429、503 | 可联调 |
| `POST /api/v1/auth/login` | 匿名 | 200 | 400、401、429、503 | 可联调 |
| `POST /api/v1/auth/refresh` | 匿名 | 200 | 400、401、503 | 可联调 |
| `POST /api/v1/auth/logout` | Bearer | 200 | 400、401、503 | 可联调 |
| `POST /api/v1/auth/password-reset/request` | 匿名 | 202 | 400、429、503 | 实现完成；集中回归待执行 |
| `POST /api/v1/auth/password-reset/confirm` | 匿名 | 200 | 400、401、409、503 | 实现完成；集中回归待执行 |
| `PUT /api/v1/auth/password` | Bearer | 200 | 400、401、409、503 | 实现完成；集中回归待执行 |
| `GET /api/v1/auth/admin/users` | ADMIN | 200 | 400、401、403 | 实现完成；账号主体脱敏，集中回归待执行 |
| `GET /.well-known/jwks.json` | 匿名 | 200 | 503 | 可联调 |

核心字段约束：

- `userId/accountId` 对外均为字符串，JavaScript 不得转为 `Number`。
- `accessToken` 是 RS256 JWT，默认 15 分钟；仅放内存并通过 `Authorization: Bearer ...` 发送。
- `refreshToken` 是不透明随机值，默认 14 天；每次刷新必须原子替换旧值，旧值不可再次使用。
- 注册和密码重置验证码为一次性 PNG，`captchaChallengeId` 与用户输入答案配对提交；校验失败后必须重新获取。
- 退出同时撤销 Refresh family 与当前 Access Session。前端无论接口结果如何都应清除本地认证状态；503 时可在不恢复页面会话的前提下后台重试。

## 5.2 稳定错误码与 HTTP 映射

| `code` | HTTP | 前端处理 |
|---|---:|---|
| `SUCCESS` | 2xx | 使用 `data`；具体 200/201/202 以接口表为准 |
| `VALIDATION_ERROR` | 400 | 显示字段校验提示，不回显密码、Token 或验证码 |
| `UNAUTHENTICATED` | 401 | 清理认证态；刷新接口出现时返回登录页 |
| `PERMISSION_DENIED` | 403 | 展示无权限页，不自动重试 |
| `RESOURCE_NOT_FOUND` | 404 | 展示资源不存在 |
| `BUSINESS_CONFLICT` | 409 | 注册时表示主体已存在或状态冲突 |
| `RATE_LIMITED` | 429 | 读取 `Retry-After` 后延迟重试 |
| `DEPENDENCY_UNAVAILABLE` | 503 | 指数退避；写操作必须保留原幂等键 |
| `INTERNAL_ERROR` | 500 | 展示通用错误并携带 `traceId` 反馈 |

OpenAPI 包含统一 Envelope Schema、Bearer 安全方案、`X-Request-Id` 参数以及 400/401/409/429/503/500 可复用响应。日志和问题反馈只允许提交 `traceId`，禁止提交密码、Refresh Token、验证码答案或完整 Authorization。

## 7. 错误码清单

错误码按领域划分，格式为 `{DOMAIN}_{REASON}`。HTTP 状态与业务码分别表达协议和业务含义。

| HTTP | 业务码 | 含义 | 前端处理 |
|---:|---|---|---|
| 400 | `VALIDATION_ERROR` | 参数校验失败 | 标注字段并展示 message |
| 401 | `UNAUTHENTICATED` | 未登录或令牌失效 | 清理会话并跳转登录 |
| 403 | `PERMISSION_DENIED` | 已登录但无权限 | 展示无权限页 |
| 404 | `RESOURCE_NOT_FOUND` | 资源不存在 | 展示空态或返回安全页面 |
| 409 | `BUSINESS_CONFLICT` | 状态冲突或重复操作 | 刷新数据并展示冲突说明 |
| 411 | `VALIDATION_ERROR` | 上传缺少 Content-Length | 使用标准 multipart 客户端重新提交 |
| 413 | `VALIDATION_ERROR` | 请求体或上传文件超过 Gateway 上限 | 压缩或拆分后重新提交 |
| 429 | `RATE_LIMITED` | 触发限流 | 按 `Retry-After` 提示重试 |
| 500 | `INTERNAL_ERROR` | 未知服务异常 | 展示 traceId，禁止暴露堆栈 |
| 503 | `DEPENDENCY_UNAVAILABLE` | 依赖服务降级 | 展示可识别降级状态 |

当前 `ygh-common-web` 已实现并测试 `BusinessException` 与未知异常的统一转换；未知异常响应不会暴露异常消息。参数校验明细、认证异常和 Gateway 异常转换将在对应模块实现时继续补充。

领域错误码将在接口评审时补充，禁止 Controller 临时拼接字符串错误码。
