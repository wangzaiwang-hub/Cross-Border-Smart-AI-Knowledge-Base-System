# 后端量化验收标准

## 1. 构建与工程结构

- Windows 使用 JDK 25 运行 Maven Wrapper，`mvnw.cmd -version` 必须显示 Java 25。
- 根工程 `mvnw.cmd clean verify` 返回 0。
- 所有 `*-service` 与 Gateway 均有独立启动类、Dockerfile、Actuator 健康端点和测试目录。
- Maven Enforcer 拒绝低于 JDK 25、未声明依赖版本、动态版本和循环模块依赖。

## 2. API 契约

- 所有外部接口位于 `/api/v1/**`。
- 100% 的 Controller 接口进入 OpenAPI，并能映射到接口清单编号。
- 分页默认 20、最大 100；超过上限返回 400 和 `VALIDATION_ERROR`。
- 所有响应包含 `code`、`message`、`data`、`traceId`、`timestamp`。
- 未登录返回 HTTP 401；无权限返回 403；资源不存在返回 404；业务状态冲突返回 409。

## 3. 测试覆盖与证据

- 金额、库存、订单状态机、权限、幂等和培训解锁规则的分支覆盖率不低于 90%。
- 公共模块和全部服务总体行覆盖率不低于 70%。
- 每个可联调接口至少有一个成功用例和一个主要失败用例。
- 集成测试验证数据库迁移、Redis、RocketMQ、PGVector 和 Elasticsearch 的关键交互。
- 不允许用禁用测试、吞异常或降低断言的方式通过构建。

## 4. 性能

- 普通查询接口 P95 ≤ 500ms。
- 普通写接口 P95 ≤ 1s，不包含模型调用。
- 商品全文搜索 P95 ≤ 1s。
- AI 首字目标 ≤ 5s，完整回答目标 ≤ 20s；超时必须返回明确状态。
- 所有外部调用设置连接与读取超时；禁止无限重试。

## 5. 安全

- 仓库 Secret 扫描不得发现真实密码、Token、私钥或 API Key。
- 普通用户访问他人地址、订单、钱包、学习记录必须返回 403 或 404，不能泄露资源存在性。
- 账号禁用后现有令牌必须失效。
- 上传接口拒绝不允许的扩展名、MIME、超限文件和路径穿越。
- 日志测试确认不输出密码、Bearer Token、完整地址和模型 Key。

## 6. 事务与幂等

- 同一 `Idempotency-Key` 重复充值或支付 10 次，只生成一次余额变化和一次有效流水。
- 同一 RocketMQ 事件重复消费 10 次，只产生一次业务结果。
- 钱包余额不得小于 0；并发扣款测试不得出现丢失更新。
- 库存锁定、确认和释放必须可对账，重复消息不得重复扣减。

## 7. 部署

- 每个场景 Compose 配置校验返回 0。
- 服务启动后 120 秒内健康检查变为 UP，否则部署失败并保留日志证据。
- 服务正确注册到 `ygh-dev` Nacos namespace，停止后实例下线。
- 虚拟机根分区使用率保持低于 80%，可用内存保持不低于 500MiB。
- 每次部署记录镜像版本、Git SHA（初始化 Git 后）、启动时间、健康状态和资源快照。

## 8. 预期验证命令

```powershell
.\mvnw.cmd clean verify
.\mvnw.cmd -Pintegration verify
docker compose config
docker compose ps
ssh vm-ygh "cd /opt/ygh/constrained-dev && ./scripts/health-check.sh"
```
