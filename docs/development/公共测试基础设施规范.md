# 公共测试基础设施规范

> 模块：`ygh-common-test`  
> 状态：`BE-0234` 已完成

## 1. Maven 使用边界

业务模块只能以 test scope 引入：

```xml
<dependency>
    <groupId>com.yuegang.zhihui</groupId>
    <artifactId>ygh-common-test</artifactId>
    <scope>test</scope>
</dependency>
```

企业 BOM 已把该依赖固定为 test scope，防止 Testcontainers、测试数据工厂和可控时钟进入生产编译/运行依赖图。`ygh-common-redis` 已作为首个复用示例，通过该模块启动真实 Redis 测试容器。

## 2. Testcontainers 工厂

`YghTestContainerFactory` 固定使用与部署基线一致的镜像：

| 工厂 | 镜像 | 内存上限 | 当前验证 |
|---|---|---:|---|
| `redis()` | `redis:8.4.4` | 128 MiB | 已真实启动、并发锁测试、停止 |
| `mysql()` | `mysql:8.4.10` | 768 MiB | 配置契约已测；真实 JDBC 见 `BE-1202` |
| `pgvector()` | `pgvector/pgvector:0.8.5-pg17-bookworm` | 512 MiB | 配置契约已测；真实 JDBC/扩展见 `BE-1202` |

数据库 Fixture 每次运行动态生成至少 192 bit 随机凭据，不使用仓库固定密码。`toString()` 永久脱敏，JDBC URL 只允许在容器启动后读取。

推荐生命周期：

```java
try (var database = YghTestContainerFactory.mysql().start()) {
    String jdbcUrl = database.jdbcUrl();
    // execute test
}
```

Fixture 实现 `AutoCloseable`，测试必须使用 try-with-resources 或 JUnit 生命周期关闭。不得把 Testcontainers 当作开发常驻组件；其容器是测试期间临时资源。

## 3. 可控时钟

`MutableTestClock`：

- 以 UTC Instant 创建，可生成不同时区 View。
- 各时区 View 共享同一原子时间源。
- `advance` 只允许正 Duration，避免无意倒退。
- `set` 用于明确的场景重置。
- 8 线程共 2000 次并发推进测试证明最终时间精确、更新线性化。

生产代码应注入 `Clock`，测试注入 `MutableTestClock`；禁止业务代码直接散落调用 `Instant.now()` 或 `OffsetDateTime.now()`。

## 4. 脱敏测试数据

`TestDataFactory(seed)` 生成可重复、唯一、显式为测试用途的数据：

- ID 以 `test-user-`、`test-order-` 开头。
- 用户名以 `test_user_` 开头。
- 邮箱只使用 IANA 保留的 `example.test` 域。
- 显示名以“测试用户”开头。
- `TestUserData.toString()` 不输出邮箱。

`TestUserData` 构造器本身也执行命名空间检查，不能绕过工厂写入真实样式身份信息。测试夹具禁止复制真实用户、员工、地址、证件号、手机号、Token 或上传文档。
