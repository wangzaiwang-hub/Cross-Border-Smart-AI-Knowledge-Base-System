## 2. Alibaba 兼容性门禁

必须逐项验证：

1. Nacos 3.1.1 服务注册、发现与配置刷新。
2. Spring Cloud Gateway 路由、Actuator 与 Jackson 3 序列化。
3. OpenFeign 同步调用、超时、错误解码和负载均衡。
4. Sentinel 1.8.9 限流、熔断与降级。
5. RocketMQ 5.3.1 生产、消费、重试和幂等。
6. Seata 2.5.0 客户端启动和必要短链路事务。
7. JDK 25 下的反射、AOT 元数据、测试和容器运行。

任何一项失败都不得通过关闭 `spring.cloud.compatibility-verifier` 解决。必须定位 4.0.7/2025.1.2 相对 Alibaba 发布基线的具体差异并留下证据。

兼容性依赖解析模块：`ygh-tests/ygh-compatibility-tests`。该模块固定引入 Actuator、Gateway WebFlux、OpenFeign、Nacos Discovery/Config、Sentinel、RocketMQ Stream 和 Seata Starter，防止 BOM 更新后只构建公共模块却遗漏实际微服务依赖。

## 5. Maven 模型解析决策

根 POM 是 `ygh-dependencies` 的父项目，因此根 POM 不能再直接导入该子 BOM，否则 Maven 在建立 reactor 前需要解析尚未构建的子模块，形成模型解析环。项目采用以下规则：

- 根 POM：聚合模块、定义 JDK/编码/插件和 Enforcer。
- `ygh-dependencies`：统一导入 Spring Boot、Spring Cloud、Spring Cloud Alibaba 并管理内部模块版本。
- 各副项目聚合 POM：导入 `ygh-dependencies`。
- 功能子项目：继承所在副项目的依赖管理，不自行声明受管版本。

## 7. MyBatis-Plus Boot 4 门禁

- 企业 BOM 固定 `mybatis-plus-spring-boot4-starter:3.5.16` 和同版本 `mybatis-plus-jsqlparser`，不使用 Boot 3 Starter。
- `ygh-common-mybatis` 通过 JDK 25 编译，并通过 Spring Boot 4.0.7 自动配置上下文加载。
- H2 MySQL 模式真实 DataSource、SqlSession 和 BaseMapper 测试验证插入、更新和分页 SQL。
- 创建审计字段在插入时由服务端强制覆盖，并使用 `updateStrategy=NEVER` 禁止参与更新。
- 分页 Guard 要求恰好一个分页拦截器、`1 <= maxLimit <= 100` 且 `overflow=false`。
- JSqlParser 生成的超大第三方解析类不参与 JaCoCo 插桩，项目生产类仍正常生成覆盖率报告。
- 2026-07-11 全 Reactor `clean verify`：9 个模块、93 项测试，0 失败、0 错误、0 跳过。

## 8. Flyway 11 前向迁移门禁

- 只允许 `classpath:db/migration` 下的 `V<正整数>__<lower_snake_case>.sql` 版本化 SQL。
- 启动前验证最终 Location、安全配置、真实解析路径、迁移类型、重复版本和历史插入，拒绝 U/R/Java Migration。
- 启动后执行官方 `validate` 校验 schema history 与 checksum；禁止生产 `clean`、自动 `repair` 和 out-of-order。
- MySQL/PostgreSQL 数据库扩展由实际 Service 按运行时引入，公共模块不绑定具体数据库。
- 详细规则与回滚方案见 `docs/development/Flyway数据库迁移规范.md`。

## 9. 覆盖率与公共 API 兼容门禁

- JaCoCo Maven Plugin 固定 `0.8.15`；有生产字节码的模块必须存在非空执行数据，否则在报告和阈值检查前失败。
- 公共模块当前按 `BUNDLE` 执行行覆盖率 `70%`、分支覆盖率 `60%` 的最低门禁；关键业务规则后续单独提升到分支 `90%`。
- `ygh-api-compatibility-tests` 固化七个公共 JAR 的 490 条公开/受保护 API 签名，同时支持目录和 JAR 扫描。
- API 变化按精确签名输出 `REMOVED/ADDED`；基线更新必须经过兼容影响审查，禁止机械接受。
- 2026-07-11 全 Reactor `clean verify`：13 个模块、176 项测试全部通过；跳过 common-core 测试的反向验证按预期被执行数据门禁阻断。
- 详细规则见 `docs/development/覆盖率与公共API兼容门禁.md`。
