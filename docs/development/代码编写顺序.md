# 跨境智汇 AI 系统代码编写顺序

## 1. 单个功能的固定编写顺序

每开发一个功能，统一按照下面的顺序编写，不跳层、不先写页面后补接口。

1. 阅读对应需求、技术规格、接口清单和现有代码，确认能否复用已有实现。
2. 定义接口契约：REST 路径、请求 DTO、响应 DTO、权限标识、错误码和幂等规则。
3. 设计数据库表、索引、约束和状态字段，并编写 Flyway 增量迁移脚本。
4. 编写 `*-api` 模块：DTO、枚举和服务间契约，不暴露数据库 Entity。
5. 编写领域层：实体、值对象、状态机、领域规则和领域事件。
6. 编写应用层：用例编排、事务边界、权限校验、幂等控制和事件发布。
7. 编写基础设施层：MyBatis/JDBC、Redis、RocketMQ、Elasticsearch、PGVector 和外部模型适配器。
8. 编写接口层：Controller、参数校验、统一响应、异常映射和 OpenAPI 注解。
9. 编写 `application.yml`、环境变量模板、健康检查和 Docker 配置。
10. 编写单元测试、集成测试、契约测试以及必要的并发或安全测试。
11. 生成并核对 OpenAPI，更新后端接口与前端接入清单。
12. 编写前端 API 类型和请求封装，再编写状态管理、页面、权限路由和交互提示。
13. 执行模块测试、Maven 构建、前端检查和实际页面验收。
14. 更新开发记录与部署说明，检查敏感信息后提交并推送 GitHub。

## 2. 整个项目的模块编写顺序

1. `ygh-dependencies`：统一依赖版本和 Maven 插件版本。
2. `ygh-common`：统一响应、异常、校验、安全、MyBatis、Redis、MQ 和测试基础设施。
3. `ygh-gateway`：路由、JWT 校验、限流、跨域、traceId 和服务发现。
4. `ygh-auth-service`：注册、登录、刷新、退出、验证码、锁定和密码管理。
5. `ygh-user` 与 `ygh-system`：用户、员工、组织、岗位、RBAC、字典和系统参数。
6. `ygh-product` 与 `ygh-inventory`：商品、SKU、价格、溯源、上下架、库存锁定与扣减。
7. `ygh-order` 与 `ygh-wallet`：购物车、订单、模拟充值、模拟支付、退款和资金流水。
8. `ygh-knowledge` 与 `ygh-search`：文档上传、解析、审核、发布、全文检索和向量检索。
9. `ygh-ai`：模型配置、企业知识库 RAG、商品与订单只读工具、联网搜索、引用和流式回答。
10. `ygh-training`：岗位学习路径、课程、章节、任务、进度、测验和统计。
11. `ygh-notification` 与 `ygh-admin`：通知补偿、运营聚合、审计和系统状态。
12. `ygh-tests`：契约、集成、端到端、安全、性能和兼容性测试。
13. `ygh-web`：商城前台、员工中心和运营后台，最后统一接入已冻结的后端契约。
14. `ygh-deploy`：镜像、Compose、虚拟机部署、监控、备份恢复和交付文档。

## 3. 单个 Maven 服务模块的文件编写顺序

```text
module/
├─ pom.xml                                      # 先确定依赖、插件和模块边界
└─ src/
   ├─ main/
   │  ├─ java/com/yuegang/zhihui/{module}/
   │  │  ├─ domain/                             # 领域模型与业务规则
   │  │  ├─ application/                        # 用例编排与事务
   │  │  ├─ infrastructure/                     # 数据库及外部组件适配
   │  │  └─ interfaces/                         # Controller 与接口转换
   │  └─ resources/
   │     ├─ db/migration/                       # Flyway 增量迁移
   │     └─ application.yml                     # 服务配置
   └─ test/
      ├─ java/                                  # 单元与集成测试
      └─ resources/                             # 测试配置和固定数据
```

纯聚合 `packaging=pom` 模块只编写 `pom.xml`，不创建空的 `src` 目录或无意义 Java 类。

## 4. 每项功能的完成顺序

```text
需求确认
→ 接口契约
→ 数据库迁移
→ API 模块
→ 领域层
→ 应用层
→ 基础设施层
→ Controller
→ 配置与容器
→ 自动化测试
→ OpenAPI 与前端接入清单
→ 前端实现
→ 构建和实际验收
→ 文档
→ Git 提交并推送
```

没有通过对应构建和验收的功能，不标记为完成；没有成功推送到 GitHub 的仓库修改，不视为已交付。
