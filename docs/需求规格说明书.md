> 文档版本：V1.2（评审稿）  
> 编制日期：2026-07-10  
> 项目形态：Java 企业级分布式系统  
> 需求依据：《需求-4天.docx》、用户补充说明、Maven 项目结构截图

## 1. 文档目的

本文档定义“粤港甄选跨境智汇 AI 知识库系统”的建设范围、用户角色、业务流程、功能需求、非功能需求和验收标准，作为产品设计、技术设计、开发、测试及验收的共同基线。

需求变更后必须同步更新本文档，并记录变更原因、影响模块、负责人和验收口径。

## 2. 项目背景

粤港甄选是一家专注于粤港澳大湾区特色农产品与食品的跨境电商企业，经营供港生鲜、岭南特产、跨境零食等品类。

当前主要问题如下：

1. 商品知识、政策法规、通关流程和物流经验分散，缺少统一知识管理体系。
2. 客户咨询量较大，人工客服难以及时、准确地回答跨境政策、商品溯源等专业问题。
3. 新员工培训周期较长，不同岗位缺少结构化、可追踪的业务学习体系。
4. 商品、订单、知识、培训和 AI 能力之间缺少统一的平台支撑。

## 3. 建设目标

1. 建设覆盖商品、政策法规、通关流程、物流及培训资料的企业知识库。
2. 建设结合知识库与商城实时商品信息的 AI 智能客服。
3. 建设支持供港生鲜、岭南特产、跨境零食等品类的在线商城。
4. 建设按岗位分配课程、采用闯关式学习并可统计进度的员工培训系统。
5. 建设统一管理后台，对用户、商品、订单、知识、AI 和培训进行运营管理。
6. 建立符合企业项目要求的权限、安全、审计、测试、部署和运维体系。

## 4. 项目范围

| 企业知识库 | 商品知识、政策法规、通关流程、物流知识、培训资料的分类、版本、审核、发布、检索和追溯 |
| AI 智能客服 | 知识问答、政策问答、通关问答、商品/溯源问答、商品推荐、引用来源、用户反馈 |
| 培训系统 | 岗位、课程、章节、文档、关卡、题库、测验、学习任务、学习进度和统计 |

### 4.2 明确不在本期范围内

1. 不接入微信、支付宝、银联等真实支付渠道。
2. 虚拟充值不产生真实资金交易。
3. 不调用真实物流或海关申报系统，不产生真实发货和清关记录。
4. 不以 AI 回答替代海关、政府部门或法律专业机构的正式意见。
5. 不在四天内承诺完成生产级全部功能；四天任务定位为工程骨架和核心流程 MVP。
6. 知识图谱在本期先使用标签、关系表和检索能力支撑，图数据库列入后续专项评估。

## 6. 核心业务流程

### 6.1 商城购买和虚拟支付

1. 用户注册并登录系统。
2. 用户浏览或搜索商品，查看价格、规格、产地、库存和溯源信息。
3. 用户将商品加入购物车或立即购买。
4. 用户选择已有地址或填写新地址。
5. 系统重新校验商品状态、价格和可用库存，生成订单预览。
6. 用户提交订单，系统锁定库存并保存商品、价格和地址快照。
7. 余额不足时，用户在个人中心进行虚拟充值。
8. 用户执行模拟支付，系统扣减虚拟余额、确认库存并生成资金流水。
9. 后台将订单推进为“模拟处理中”和“模拟完成”。
10. 全流程不调用真实支付、物流或发货接口。

### 6.2 知识入库与发布

1. 知识运营员上传文档并填写分类、来源、地区、发布日期、生效日期、失效日期、版本和密级。
2. 系统进行文件格式、大小、重复内容和安全校验。
3. 系统解析正文并生成切片，但文档仍处于待审核状态。
4. 知识审核员核对来源和内容，执行通过或驳回。
5. 审核通过后发布知识版本。
6. 发布事件触发全文索引和向量索引构建。
7. 新版本发布后保留旧版本，但旧版本不再作为默认召回内容。
8. 已失效或已下线内容不得继续作为外部 AI 回答的有效依据。

### 6.3 AI 客服问答

1. 系统接收用户问题并识别意图、身份和会话上下文。
2. 对政策、通关和知识问题执行查询改写及权限过滤。
3. 使用 PGVector 完成语义检索，使用 Elasticsearch 完成关键词检索。
4. 对检索结果进行融合排序，构造受控上下文。
5. 对商品、库存、价格和订单问题，通过受控 Java 工具调用访问业务服务。
6. LangChain4j 调用豆包模型生成答案。
7. 答案显示引用文档、版本和更新时间。
8. 证据不足时明确说明无法确认，并建议查看官方信息或联系人工客服。
9. 系统记录脱敏后的问答、检索证据、耗时、模型版本和用户反馈。

### 6.4 闯关式培训

1. 培训管理员按岗位创建课程和学习路径。
2. 每门课程包含章节、文档、关卡和测验。
3. 管理员将课程分配给岗位、部门或员工。
4. 系统为员工生成学习任务和截止时间。
5. 员工阅读课程文档，系统记录阅读位置和有效学习时长。
6. 员工完成当前关卡要求和测验后解锁下一关。
7. 未通过测验时，按课程配置重新学习或重试。
8. 管理员查看完成率、逾期率、成绩和薄弱知识点。

## 8. 非功能需求

### 8.1 性能

| 指标 | 目标值 |
|---|---|
| 普通查询接口 | P95 不高于 500ms |
| 商品全文搜索 | P95 不高于 1s |
| 普通写接口 | P95 不高于 1s，不包含外部模型调用 |
| AI 首字响应 | 目标不高于 5s，受模型与网络影响 |
| AI 完整回答 | 目标不高于 20s，超时应给出明确提示 |
| 批量文档处理 | 必须异步执行，可查询进度和失败原因 |

### 8.2 可靠性与一致性

1. 充值、支付、下单、取消、库存和消息消费接口必须支持幂等。
2. 钱包、订单和库存必须提供对账机制。
3. RocketMQ 按至少一次投递设计，消费者必须保证业务结果不重复。
4. Elasticsearch 和 PGVector 属于派生索引，失败后必须能够重试或重建。
5. 数据库为业务事实来源，Redis、Elasticsearch 和向量库不得成为交易数据唯一来源。
6. 服务调用必须设置超时、熔断和有限重试，禁止无限重试。

### 8.3 安全

1. 全部外部访问采用 HTTPS。
2. 使用强密码散列算法保存密码，禁止明文或可逆加密。
3. 实施 RBAC、数据所有权校验和最小权限原则。
4. 防止 SQL 注入、越权访问、XSS、CSRF、恶意上传和暴力登录。
5. 豆包 API Key、数据库密码、JWT 密钥不得写入源码或提交 Git。
6. 日志不得打印密码、访问令牌、完整地址和其他敏感信息。
7. 用户问题发送给模型前应进行敏感信息最小化处理。
8. 上传文件必须限制格式、大小和访问权限，并执行安全校验。

### 8.4 可维护性

1. 使用 Java 25 LTS 和 Maven Wrapper。
2. 所有依赖版本由根项目 BOM 统一管理。
3. 使用统一响应结构、异常码、日志格式和 traceId。
4. 数据库变更使用版本化迁移脚本。
5. 提供 OpenAPI 接口文档和关键业务时序说明。
6. 禁止跨微服务直接访问其他服务数据库。
7. 重要业务规则必须具备单元测试。

### 8.5 可观测性

1. 采集 JVM、HTTP、MySQL、Redis、RocketMQ、Elasticsearch 和 PGVector 指标。
2. 记录 AI 检索、重排、模型调用、首字时间、完整响应和异常指标。
3. 所有同步调用和消息事件传播 traceId。
4. 对错误率、慢接口、消息积压、数据库连接池和磁盘水位配置告警。

### 8.6 容量假设

首期暂按以下规模设计，详细设计前需要由项目负责人确认：

- 商品数量：10 万。
- 注册用户：1 万。
- 峰值请求：200 QPS。
- 知识文档：5 万份。
- 文档切片：百万级。

若真实规模与上述假设明显不同，必须重新进行容量估算和性能测试。

## 9. 数据保留和备份要求

1. MySQL、PostgreSQL/PGVector、Nacos 配置和附件必须定期备份。
2. 订单、钱包和审计记录不得物理随意删除。
3. Elasticsearch 索引允许从业务数据重建，但仍需保留配置和重建脚本。
4. 备份文件必须限制访问权限，并定期执行恢复演练。
5. 正式环境 RPO、RTO 和数据保留年限由项目负责人在上线前确认。

## 10. 验收场景

### AC-01 商城核心链路

用户能够注册登录，完成虚拟充值、选择商品、填写地址、下单、模拟支付并查看订单状态；全过程不产生真实资金和真实发货。

### AC-02 库存和钱包幂等

重复提交支付请求或重复消费 RocketMQ 消息时，不重复扣减虚拟余额或库存，并能查询对应业务流水。

### AC-03 知识发布

运营员上传政策文档并提交审核，审核员发布后，系统完成全文和向量索引；下线后不再出现在外部 AI 检索结果中。

### AC-04 AI 专业问答

用户询问政策、通关流程、商品溯源或商品推荐时，AI 能结合已发布知识和实时商品信息回答，并显示引用来源；证据不足时不臆测。

### AC-05 闯关式培训

管理员按岗位发布课程，员工完成文档学习和测验后更新学习进度并解锁下一关，后台统计与个人记录一致。

### AC-06 权限隔离

普通用户无法访问管理接口、他人订单、他人钱包或内部知识；不同运营岗位只能使用授权功能。

### AC-07 资源受限 DEV 部署

虚拟机常驻 MySQL、Redis、Nacos、Gateway、Auth 和 User，并能按商城、AI、培训场景切换对应 Java 服务组；本机 Docker 按场景提供 RocketMQ/Seata 或 PGVector/Elasticsearch。每次切换后健康检查和对应端到端场景必须通过。同时交付不依赖本机的企业服务器 Compose 清单，明确当前结果不代表生产容量或高可用验收。

### AC-08 项目质量

`mvn clean verify` 执行成功，核心单元测试、集成测试、接口回归和部署冒烟测试通过，P0/P1 缺陷清零。
