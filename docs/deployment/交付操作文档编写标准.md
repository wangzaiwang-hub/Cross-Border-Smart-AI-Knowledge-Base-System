# 跨境智汇 AI 知识库系统交付操作文档编写标准

## 一、编写前必须核对项目

每写一个组件的安装或配置文档，先检查项目中的 Compose、应用配置、部署目录、版本锁定文件和实际环境台账。不能只根据通用教程判断组件装在哪里、如何启动。

至少确认以下内容：

1. 组件运行在 Windows 本机、Windows Docker Desktop、WSL2、Rocky Linux 虚拟机宿主系统，还是虚拟机 Docker 容器。
2. 组件由 Docker Compose、独立 Docker 容器、系统服务还是 IDEA 管理。
3. 项目固定版本、镜像名称、端口、数据目录、配置文件、数据卷和资源限制。
4. 哪些 Java 服务使用该组件，实际读取哪些环境变量。
5. 该组件和其他组件的启动依赖、健康检查及停止顺序。

## 二、主流程只能写项目标准方案

客户第一次部署时需要执行的标准方案必须放在文档最前面，并按真实顺序编号。通用安装、源码安装、旧数据迁移和替代方案只能放在后面的明确附录中。

同一个组件不能在主流程中同时提供两套互相冲突的启动方式。例如项目 Redis 由 `vm-compose.yml` 管理，主流程就不能再用独立 `docker run` 创建第二个 Redis 容器。

## 三、每一步必须写清四项内容

每个步骤都必须包含：

1. **在哪里操作**：明确是 Windows PowerShell、Windows 图形界面、IDEA、WinSCP、虚拟机 SSH 终端还是容器内部。
2. **输入或点击什么**：给出完整命令，或逐项写清菜单、按钮、输入框和填写值。
3. **执行后的结果**：写出正常输出、状态、文件位置或界面变化。
4. **需要修改的内容**：指出 IP、用户名、密码、盘符、网卡名等客户差异项，以及具体修改方法。

不能只给一串命令而不解释结果，也不能只讲原理而没有下一步操作。

## 四、安装位置必须写在对应步骤

不要只在文档开头集中列一张环境表。安装每个软件或复制每个文件时，当步写清安装到哪里、配置放在哪里、数据保存在哪里，以及明确不安装到哪些环境。

## 五、启动方式必须符合交付习惯

- Java 后端服务由 Windows 本机 IntelliJ IDEA 启动，写清 Run Configuration 和环境变量，不提供批量启动脚本作为客户主流程。
- 前端由 Windows 本机 PowerShell 启动。
- MySQL、Redis、Nacos、PGVector 由 Rocky Linux 虚拟机中的 Docker Compose 管理。
- RocketMQ、Seata、Elasticsearch 按项目场景由 Windows Docker Desktop 管理。
- WSL2 是 Docker Desktop 后端环境，不作为本项目代码和 Java 服务的运行位置。

## 六、配置必须来自项目真实文件

版本、端口、镜像、变量名、健康检查和资源限制必须引用仓库当前文件，不凭记忆填写。文档修改后再次和以下内容交叉检查：

- `ygh-deploy/constrained-dev/vm-compose.yml`
- `ygh-deploy/constrained-dev/local-compose.yml`
- `ygh-deploy/constrained-dev/.env.example`
- 各服务的 `application.yml`
- `docs/development/环境配置台账.md`

## 七、保留原资料时必须划清适用范围

用户提供的原始教程中，源码包、配置文件、安装目录、数据目录和迁移细节不能无故删除。若原教程与项目标准部署不同，应完整保留为“旧环境迁移”或“补充操作”，同时明确：

- 哪些客户需要执行。
- 哪些客户必须跳过。
- 最终数据和配置如何进入项目标准运行方式。
- 哪些旧命令不能和项目主流程同时执行。

## 八、完成前必须验证

至少检查：

1. 文档命令中的路径、文件名、服务名和变量名在仓库中真实存在。
2. 安装顺序符合组件依赖关系。
3. 主流程只有一个明确结果。
4. 代码围栏和 Markdown 结构完整。
5. 文档不包含真实密码、Token、API Key 或客户敏感信息。
6. 停止和清理命令不会误删数据卷；危险命令必须给出明确警告。
