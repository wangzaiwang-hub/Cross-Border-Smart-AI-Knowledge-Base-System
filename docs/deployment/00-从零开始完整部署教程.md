# 跨境智汇 AI 知识库系统从零开始完整部署教程

本教程是整套交付文档的唯一执行顺序。客户从 `01` 开始，完成当前文档规定的检查结果后，才能进入下一份文档。项目不提供也不使用批处理、Shell、PowerShell、Python 部署脚本、Maven Wrapper、`.env` 或 Docker Compose 启动项目；系统安装、镜像拉取、容器创建、数据库初始化和健康检查全部由操作人员逐条输入命令，14 个 Java 服务和两个前端全部在 IDEA 中逐个建立运行配置。

Flyway 的 `src/main/resources/db/migration/*.sql` 是 Java 服务管理数据库结构所必需的版本文件，不是部署脚本，不能删除。

## 第一步：创建 Rocky Linux 10.2 虚拟机并安装 Docker Engine

**在哪里操作**：VMware 下载、安装和网络配置在客户 Windows 本机；Rocky Linux 命令在虚拟机控制台或 Windows SSH 终端执行。

打开并从第一步执行到最后一步：

[01-Rocky Linux 虚拟机从零配置指南](./01-Rocky%20Linux虚拟机从零配置指南.md)

必须依次完成：

1. 安装 VMware Workstation Pro。
2. 创建 VMnet8 NAT 网络 `192.168.154.0/24`。
3. 下载并安装 Rocky Linux 10.2 x86_64 Minimal。
4. 设置虚拟机固定地址 `192.168.154.10`、网关和 DNS。
5. 启动 SSH 并从 Windows 登录虚拟机。
6. 在虚拟机中手工安装 Docker Engine。
7. 逐个检测镜像地址并配置当前网络可用的镜像源。
8. 配置虚拟机防火墙。

在 Windows PowerShell 逐条输入：

```powershell
Test-NetConnection 192.168.154.10 -Port 22
ssh wang@192.168.154.10 'cat /etc/rocky-release'
ssh wang@192.168.154.10 'ip -4 address show'
ssh wang@192.168.154.10 'docker version --format "{{.Server.Version}}"'
```

**执行后的结果**：第一条命令显示 `TcpTestSucceeded : True`；后面三条分别显示 Rocky Linux 10.2、`192.168.154.10/24` 和 Docker 服务端版本。

**哪些内容需要修改**：客户用户名不是 `wang` 时替换每条 SSH 命令中的用户名；现场不能使用 `192.168.154.0/24` 时，记录虚拟机实际 IP 和 Windows VMnet8 IP，后续所有文档同时替换，不能只修改某一处。

## 第二步：在虚拟机 Docker 中安装 MySQL 8.4.10

**在哪里操作**：Rocky Linux SSH 终端；SQL 文件上传在 Windows WinSCP；端口检查在 Windows PowerShell。

打开：

[02-MySQL 8.4.10 Docker 镜像手工安装与项目配置操作文档](./02-MySQL-8.4.10-Docker镜像手工安装与项目配置操作文档.md)

本阶段依次完成镜像拉取、目录和配置文件创建、root 密码文件、`ygh-core` Docker 网络、MySQL 容器、11 个项目数据库、Nacos 数据库表以及 app/migration 数据库账号。

本阶段**不要执行**该文档“在 IDEA 中确认源码和 Flyway”部分，因为 Windows 的 JDK、Maven、IDEA 和源码尚未准备。该部分统一在本教程第十一步执行。

完成后在 Windows PowerShell 逐条输入：

```powershell
Test-NetConnection 192.168.154.10 -Port 3306
ssh wang@192.168.154.10 'docker ps --filter name=^ygh-mysql$ --format "{{.Names}} {{.Status}} {{.Ports}}"'
```

**执行后的结果**：3306 显示 `True`，`ygh-mysql` 显示 `Up` 和 `healthy`。MySQL 未健康时不能继续安装 Nacos。

必须先确认 MySQL 中已经存在 `nacos_config` 数据库、Nacos 数据库账号和项目提供的 Nacos 表。随后逐项完成镜像、数据库密码文件、三项认证参数、Nacos 容器、管理员初始化、`ygh-dev` 命名空间和防火墙。

本阶段执行到 Nacos 控制台、命名空间和 Windows 连通性验证完成为止。文档中的 IDEA 服务注册验证统一延后到本教程第十一步。


**执行后的结果**：三个端口均显示 `True`，readiness 返回正常状态；浏览器可以登录 `http://192.168.154.10:8848/nacos/`，并能切换到 `ygh-dev` 命名空间。

## 第六步：在 Windows 安装 WSL2 和 Docker Desktop

**在哪里操作**：客户 Windows 本机，不进入 Rocky Linux 虚拟机。

打开并完整执行：

[06-Windows WSL2 与 Docker Desktop 手工安装配置操作文档](./06-Windows-WSL2与Docker-Desktop手工安装配置操作文档.md)

## 第十一步：在 IDEA 迁移数据库并逐个启动 14 个 Java 服务

**在哪里操作**：Windows IntelliJ IDEA；端口和健康检查在 Windows PowerShell。

打开并严格按小节顺序执行：

[11-Windows IDEA 14 个 Java 服务手工配置与启动操作文档](./11-Windows-IDEA-14个Java服务手工配置与启动操作文档.md)

首先在 Windows 本机手工建立密钥目录并生成四类互不相同的密钥和 JWT RSA 密钥。然后在 IDEA 中分别创建并运行：

```text
DB-Migrate-auth
DB-Migrate-user
DB-Migrate-system
```

三个迁移配置必须分别显示 `Process finished with exit code 0`。随后按 MySQL 文档的授权步骤，逐表授予 auth、user、system 的 app 账号权限。

普通 Java 服务按以下依赖顺序逐个创建 IDEA `Application` 配置、逐项填写环境变量、点击 `Run` 并检查健康状态：

```text
User → System → Notification → Auth → Gateway → Inventory → Wallet
→ Search → Product → Order → Knowledge → AI → Training → Admin
```

不能给 14 个服务复制同一组变量。每个服务看到 `Started ...Application` 且 `/actuator/health` 为 `UP` 后，才能配置下一个服务。

启动 Training 前，在 Windows PowerShell 输入：

```powershell
docker stop ygh-seata
Test-NetConnection 127.0.0.1 -Port 8091
```

**执行后的结果**：第一条返回 `ygh-seata`，第二条应显示 `TcpTestSucceeded : False`。此时才能在 IDEA 启动 Training。

## 第十二步：在 IDEA 逐个启动商城前端和管理前端

**在哪里操作**：Windows IntelliJ IDEA、IDEA Terminal 和浏览器。

[12-Windows IDEA 商城与管理前端手工配置启动操作文档](./12-Windows-IDEA-商城与管理前端手工配置启动操作文档.md)

两个配置的 `VITE_GATEWAY_URL` 均填写 `http://127.0.0.1:8080`。先启动当前验收场景需要的 Java 服务和 Gateway，再逐个启动两个前端。

## 第十四步：逐项检查容器和数据卷

**在哪里操作**：Windows PowerShell 和 Rocky Linux SSH 终端。

先在 Windows PowerShell 输入：

```powershell
docker ps -a --format 'table {{.Names}}\t{{.Image}}\t{{.Status}}\t{{.Ports}}'
docker volume ls
```

再登录虚拟机：

```powershell
ssh wang@192.168.154.10
```

进入虚拟机后逐条输入：

```bash
docker ps -a --format 'table {{.Names}}\t{{.Image}}\t{{.Status}}\t{{.Ports}}'
docker volume ls
exit
```

**执行后的结果**：容器名称、镜像版本和端口与各组件文档一致，MySQL、Redis、PGVector、RocketMQ、Seata 和 Elasticsearch 数据卷仍然存在。

日常停止只输入 `docker stop 容器名`，恢复只输入 `docker start 容器名`。不要执行删除数据卷或清理全部 Docker 数据的命令。
