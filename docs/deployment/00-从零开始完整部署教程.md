# 跨境智汇 AI 知识库系统从零开始完整部署教程

本交付版本不包含项目批处理、Shell、PowerShell、Python 部署脚本或 Maven Wrapper。所有系统安装、镜像拉取、容器创建、数据库初始化、备份恢复和健康检查都在对应文档中逐条输入命令；14 个 Java 服务全部在 IDEA 中逐个创建 `Application` 运行配置并启动。Flyway 的 `db/migration/*.sql` 是数据库版本代码，必须保留，不是部署批处理。

## 第一步：在 Windows 安装 WSL2 和 Docker Desktop

**在哪里操作**：客户 Windows 11 本机，不是在虚拟机或 SSH 终端。

打开并从第一步到最后一步完整执行：

[Windows WSL2 与 Docker Desktop 手工安装配置操作文档](./06-Windows-WSL2与Docker-Desktop手工安装配置操作文档.md)

该文档会完成：

1. 检查 Windows 版本、CPU 虚拟化和内存。
2. 启用 WSL2，安装 Ubuntu 作为 Docker Desktop 后端。
3. 从 Docker 官方网站下载并安装 Docker Desktop。
4. 配置 CPU、内存、磁盘和镜像访问。
5. 手工拉取并运行 Alpine 测试镜像。

完成后在 Windows PowerShell 输入：

```powershell
wsl --version
docker version
docker info --format 'OS={{.OSType}} Arch={{.Architecture}} CPUs={{.NCPU}} Memory={{.MemTotal}}'
docker run --rm alpine:latest echo DOCKER_DESKTOP_OK
```

**执行后的结果**：WSL 版本正常，Docker 同时显示 Client 和 Server，系统为 Linux/x86_64，最后输出 `DOCKER_DESKTOP_OK`。

**下一步做什么**：Docker Desktop 验证成功后创建 Rocky Linux 虚拟机。

## 第二步：创建 Rocky Linux 10.2 虚拟机并安装 Docker Engine

**在哪里操作**：VMware 安装和网络配置在 Windows；Linux 命令通过 Windows SSH 登录虚拟机后执行。

完整执行：

[Rocky Linux 虚拟机从零配置指南](./01-Rocky%20Linux虚拟机从零配置指南.md)

严格按文档顺序完成：

1. VMware VMnet8 NAT 网段设为 `192.168.154.0/24`。
2. 下载并校验 Rocky Linux 10.2 x86_64 Minimal ISO。
3. 创建虚拟机并安装 Rocky Linux。
4. 将虚拟机固定为 `192.168.154.10`。
5. 修复网关和 DNS，确认虚拟机可以访问互联网。
6. 启用 SSH。
7. 在虚拟机安装 Docker Engine。
8. 逐个测试 Docker Hub 或合规镜像源。
9. 只允许 Windows VMnet8 地址访问项目端口。

完成后在 Windows PowerShell 输入：

```powershell
Test-NetConnection 192.168.154.10 -Port 22
ssh wang@192.168.154.10 'cat /etc/rocky-release; ip -4 address; docker version --format "{{.Server.Version}}"'
```

**执行后的结果**：SSH 为 `True`，系统显示 Rocky Linux 10.2，虚拟机地址为 `192.168.154.10/24`，Docker 输出服务端版本。

**需要修改的内容**：用户名不是 `wang` 时替换 SSH 用户名；现场网段不同时，后面所有 `192.168.154.10` 和 `192.168.154.1` 都按虚拟机指南记录的实际值替换。

## 第十二步：按业务场景选择中间件和 Java 服务

**在哪里操作**：Windows Docker Desktop、PowerShell 和 IDEA。

当前电脑资源有限，不要求全部中间件和 14 个服务一直同时运行。

### 基础认证场景

按 IDEA 文档依次启动 User、System、Notification、Auth、Gateway。

### 商城场景

保持 RocketMQ 运行，Java 服务的 MQ 开关改为文档指定的 `true`，再启动 Inventory、Wallet、Search、Product、Order。Seata当前只做组件交付验证，不是 Java 服务的启动前提。

### 知识库与 AI 场景

保持 PGVector 和 Elasticsearch 运行，依次启动 System、Search、Knowledge；AI 需要的 Product、Inventory、Order就绪后再启动 AI。

### 培训场景

先输入：

```powershell
docker stop ygh-seata
```

确认 8091 释放后，再在 IDEA 启动 Training。停止 Training 后才可以执行 `docker start ygh-seata`。

## 第十四步：执行最终连通性检查

**在哪里操作**：Windows PowerShell。

输入：

```powershell
$checks=@(
  @{Name='MySQL';Host='192.168.154.10';Port=3306},
  @{Name='Redis';Host='192.168.154.10';Port=6379},
  @{Name='Nacos';Host='192.168.154.10';Port=8848},
  @{Name='PGVector';Host='192.168.154.10';Port=5432},
  @{Name='RocketMQ';Host='127.0.0.1';Port=19876},
  @{Name='Elasticsearch';Host='127.0.0.1';Port=19200},
  @{Name='Gateway';Host='127.0.0.1';Port=8080},
  @{Name='Mall';Host='127.0.0.1';Port=5173},
  @{Name='AdminWeb';Host='127.0.0.1';Port=5174}
)
$checks | ForEach-Object {
  $ok=Test-NetConnection $_.Host -Port $_.Port -InformationLevel Quiet
  [pscustomobject]@{Name=$_.Name;Address="$($_.Host):$($_.Port)";Succeeded=$ok}
} | Format-Table -AutoSize
```

**执行后的结果**：当前场景需要的项目全部为 `True`。未启用的可选场景组件可以为 `False`，但必须在交付记录中标明“本场景未启动”，不能写成已验证。

## 第十五步：检查容器、服务和数据不被误删

**在哪里操作**：Windows PowerShell 和 Rocky Linux SSH。

```powershell
docker ps -a --format 'table {{.Names}}\t{{.Image}}\t{{.Status}}\t{{.Ports}}'

```

虚拟机容器输入：

```powershell
ssh wang@192.168.154.10 'docker ps -a --format "table {{.Names}}\t{{.Image}}\t{{.Status}}\t{{.Ports}}"; docker volume ls'
```

**执行后的结果**：容器镜像版本与组件文档一致，数据卷仍存在。日常停止使用 `docker stop 容器名`，再次启动使用 `docker start 容器名`。不要执行带数据卷删除参数的命令。
