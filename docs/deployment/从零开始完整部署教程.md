# 跨境智汇 AI 系统：从零开始完整部署教程

## 第一步：准备 Windows

客户电脑先安装 Git、JDK、IDEA、Node.js、Docker Desktop 和 WSL2。后端 Java 服务在 IDEA 中启动，前端在 Windows 中启动，本机 Docker Desktop 只用于 RocketMQ、Seata 或 Elasticsearch 场景组件。

### 第一步-1：确认 Windows 版本和内存

按 `Win + R`，输入 `winver`，按回车。建议使用 Windows 11 22H2 或更新版本。

打开 PowerShell，执行：

```powershell
Get-ComputerInfo | Select-Object WindowsProductName,WindowsVersion,OsTotalVisibleMemorySize
```

预期看到 Windows 名称、版本号和内存数字。当前方案按约 15GB 物理内存设计。

### 第一步-2：下载和安装 Git

安装位置：

```text
安装到 Windows 本机电脑。
默认安装路径：C:\Program Files\Git
命令路径：C:\Program Files\Git\cmd\git.exe
用途：Windows PowerShell、IDEA、项目拉取代码使用。
不安装到：Rocky Linux 虚拟机、WSL2、Docker 容器。
```

官方下载地址：

- Git for Windows：https://git-scm.com/download/win

推荐安装方式一：使用 `winget` 自动下载并安装。

以管理员身份打开 PowerShell：

```powershell
winget install --id Git.Git -e --source winget
git --version
```

预期输出类似 `git version 2.x.x.windows.x`。如果第二条命令提示找不到，关闭当前 PowerShell 后重新打开。

推荐安装方式二：浏览器手动安装。

1. 打开 https://git-scm.com/download/win。
2. 点击 `64-bit Git for Windows Setup` 下载安装包。
3. 双击安装包。
4. 安装过程保持默认选项即可，关键选项建议如下：
   - `Git from the command line and also from 3rd-party software`。
   - `Use bundled OpenSSH`。
   - `Checkout Windows-style, commit Unix-style line endings`。
   - 默认终端选择 `Use Windows' default console window` 或 `MinTTY` 均可。
5. 安装完成后重新打开 PowerShell，执行 `git --version`。

### 第一步-3：下载和安装 JDK 25

安装位置：

```text
安装到 Windows 本机电脑。
默认安装路径示例：C:\Program Files\Eclipse Adoptium\jdk-25.0.3.7-hotspot
环境变量：JAVA_HOME 指向 JDK 25 安装目录。
用途：IDEA 启动后端 Java 服务、Maven 构建项目。
不安装到：Rocky Linux 虚拟机、WSL2、Docker 容器。
```

官方下载地址：

- Eclipse Temurin JDK 25：https://adoptium.net/temurin/releases/?version=25
- Oracle JDK 25：https://www.oracle.com/java/technologies/downloads/

本项目推荐 Eclipse Temurin JDK 25。推荐安装方式一：使用 `winget`。

```powershell
winget search Temurin 25
winget install --id EclipseAdoptium.Temurin.25.JDK -e
java -version
```

预期第一行包含 `openjdk version "25` 。项目实测版本为 25.0.3。

如果 `java -version` 仍显示旧版本：

```powershell
Get-ChildItem 'C:\Program Files\Eclipse Adoptium' -Directory
```

在“系统属性 → 高级 → 环境变量”中将 `JAVA_HOME` 设为列出的 JDK 25 目录，并把 `%JAVA_HOME%\bin` 放到 `Path` 前部。

手动配置环境变量步骤：

1. 右键“此电脑” → “属性” → “高级系统设置” → “环境变量”。
2. 在下面的“系统变量”区域点击“新建”。如果已经有 `JAVA_HOME`，就选中它后点击“编辑”。
3. 变量名填写：

```text
JAVA_HOME
```

4. 变量值填写 JDK 25 的安装目录，示例：

```text
C:\Program Files\Eclipse Adoptium\jdk-25.0.3.7-hotspot
```

注意：

```text
JAVA_HOME 只写到 JDK 根目录，不要写 \bin。
正确：C:\Program Files\Eclipse Adoptium\jdk-25.0.3.7-hotspot
错误：C:\Program Files\Eclipse Adoptium\jdk-25.0.3.7-hotspot\bin
```

5. 在“系统变量”里找到 `Path`，选中后点击“编辑”。
6. 点击“新建”，填写：

```text
%JAVA_HOME%\bin
```

7. 把 `%JAVA_HOME%\bin` 移到旧版 Java 路径前面。
8. 如果 `Path` 里还有旧版 JDK，例如 `C:\Program Files\Java\jdk-17\bin`，删除或下移。
9. 一路点击“确定”，关闭所有环境变量窗口。
10. 关闭当前 PowerShell，重新打开一个新的 PowerShell，执行：

```powershell
java -version
where java
echo $env:JAVA_HOME
```

预期结果：

```text
java -version 第一行包含 openjdk version "25
where java 第一行来自 C:\Program Files\Eclipse Adoptium\jdk-25...\bin\java.exe
echo $env:JAVA_HOME 输出 C:\Program Files\Eclipse Adoptium\jdk-25...
```

如果客户习惯用命令配置，也可以用管理员 PowerShell 写入系统环境变量。先确认实际 JDK 目录：

```powershell
Get-ChildItem 'C:\Program Files\Eclipse Adoptium' -Directory
```

假设实际目录是 `C:\Program Files\Eclipse Adoptium\jdk-25.0.3.7-hotspot`，执行：

```powershell
[Environment]::SetEnvironmentVariable('JAVA_HOME','C:\Program Files\Eclipse Adoptium\jdk-25.0.3.7-hotspot','Machine')
```

继续执行：

```powershell
$machinePath = [Environment]::GetEnvironmentVariable('Path','Machine')
if ($machinePath -notlike '*%JAVA_HOME%\bin*') {
  [Environment]::SetEnvironmentVariable('Path', "%JAVA_HOME%\bin;$machinePath", 'Machine')
}
```

执行后的结果：

关闭 PowerShell，重新打开，再执行 `java -version`、`where java`、`echo $env:JAVA_HOME`，结果必须指向 JDK 25。

### 第一步-4：下载和安装 IntelliJ IDEA

安装位置：

```text
安装到 Windows 本机电脑。
默认安装路径示例：C:\Program Files\JetBrains\IntelliJ IDEA 20xx.x
项目打开路径：F:\跨境智汇AI知识库系统
用途：逐个启动 Spring Boot 后端服务。
不安装到：Rocky Linux 虚拟机、WSL2、Docker 容器。
```

官方下载地址：

- IntelliJ IDEA：https://www.jetbrains.com/idea/download/

建议使用 IntelliJ IDEA Ultimate。如果客户只有 Community Edition，也可以运行普通 Spring Boot 主类，但缺少部分 Spring 配置辅助能力。

安装步骤：

1. 打开 https://www.jetbrains.com/idea/download/。
2. 选择 Windows 版本，下载 `Ultimate` 安装包。
3. 双击安装包。
4. 建议勾选：
   - `Create Desktop Shortcut`。
   - `Add "bin" folder to the PATH`。
   - `.java` 文件关联可按客户习惯选择。
5. 安装完成后打开 IDEA，首次启动按提示登录 JetBrains 账号或使用许可证。
6. 在 IDEA 中进入 `File → Settings → Build, Execution, Deployment → Build Tools → Maven`：
   - `Maven home path` 选择 `Use Maven wrapper` 或项目自带 `.mvn/wrapper`。
   - `JDK for importer` 选择 JDK 25。
7. 进入 `File → Project Structure → Project`：
   - `SDK` 选择 JDK 25。
   - `Language level` 选择 `25`。

### 第一步-5：下载和安装 Node.js 和 pnpm

安装位置：

```text
Node.js 安装到 Windows 本机电脑。
Node.js 默认安装路径：C:\Program Files\nodejs
pnpm 由 Corepack 启用，运行在 Windows PowerShell。
前端项目路径：F:\跨境智汇AI知识库系统\ygh-web
用途：启动和构建商城前端、管理端前端。
不安装到：Rocky Linux 虚拟机、WSL2、Docker 容器。
```

官方下载地址：

- Node.js LTS：https://nodejs.org/en/download
- pnpm：https://pnpm.io/installation

推荐安装方式：先安装 Node.js LTS，再用 Corepack 启用 pnpm。

```powershell
winget install --id OpenJS.NodeJS.LTS -e
node --version
corepack enable
corepack prepare pnpm@10.13.1 --activate
pnpm --version
```

预期 `pnpm --version` 输出 `10.13.1`。

如果浏览器手动安装：

1. 打开 https://nodejs.org/en/download。
2. 选择 Windows Installer `.msi`。
3. 双击安装，保持默认选项。
4. 重新打开 PowerShell，执行 `node --version`。
5. 再执行 `corepack enable` 和 `corepack prepare pnpm@10.13.1 --activate`。

### 第一步-6：安装 WSL2 Ubuntu

安装位置：

```text
安装到 Windows 本机电脑内部。
用途：作为 Docker Desktop 的 WSL2 后端环境。
Ubuntu 用户数据由 Windows 管理，通常在用户目录下的 WSL 数据目录中。
本项目不放到 WSL2 里运行，不在 WSL2 里启动 Java，不在 WSL2 里启动前端。
```

官方下载和说明地址：

- WSL 官方文档：https://learn.microsoft.com/windows/wsl/install
- Microsoft Store Ubuntu：https://apps.microsoft.com/detail/9pdxgncfsczv

以管理员身份执行：

```powershell
wsl --install -d Ubuntu
```

安装结束后重启电脑。第一次打开 Ubuntu 时，按提示输入 Linux 用户名和密码。输入密码时屏幕不显示字符是正常现象。

验证：

```powershell
wsl --status
wsl --list --verbose
```

预期 Ubuntu 的 `VERSION` 为 `2`。

如果 `wsl --install` 下载慢，可以先从 Microsoft Store 安装 Ubuntu，再执行 `wsl --set-default-version 2`。

### 第一步-7：下载和安装 Docker Desktop

安装位置：

```text
安装到 Windows 本机电脑。
默认安装路径：C:\Program Files\Docker\Docker
配置文件位置：%UserProfile%\.wslconfig
容器实际运行环境：Windows 的 Docker Desktop + WSL2 backend。
用途：运行 Windows 本机场景组件 RocketMQ、Seata、Elasticsearch。
不用于运行：虚拟机里的 MySQL、Redis、Nacos、PGVector。
```

官方下载地址：

- Docker Desktop for Windows：https://www.docker.com/products/docker-desktop/
- Docker 官方安装文档：https://docs.docker.com/desktop/setup/install/windows-install/

推荐安装方式一：使用 `winget`。

```powershell
winget install --id Docker.DockerDesktop -e
```

重启 Windows，打开 Docker Desktop，第一次使用时：

1. 接受许可协议。
2. Settings → General，勾选“Use the WSL 2 based engine”。
3. Settings → Resources → WSL Integration，打开 Ubuntu。
4. 本机低配模式使用项目已配置的 3GB 上限；如需重新配置，先备份 `%UserProfile%\.wslconfig`，再参考 `ygh-deploy/host/wslconfig.template`。

验证：

```powershell
docker version
docker info --format 'Docker memory: {{.MemTotal}} bytes'
docker run --rm hello-world
```

预期最后一条命令显示 `Hello from Docker!`。

> 不要在 Docker Desktop 运行期间执行 `wsl --terminate Ubuntu`。如必须重启 WSL，依次执行 `docker desktop stop`、`wsl --shutdown`、`wsl -d Ubuntu --exec true`、`docker desktop start`。

手动安装方式：

1. 打开 https://www.docker.com/products/docker-desktop/。
2. 点击 `Download for Windows`。
3. 双击 `Docker Desktop Installer.exe`。
4. 安装时保持 `Use WSL 2 instead of Hyper-V` 勾选。
5. 安装完成后重启 Windows。
6. 打开 Docker Desktop，按上面的 Settings 配置 WSL 2 engine 和 Ubuntu integration。

### 第一步-8：配置 Docker Desktop 资源上限

配置位置：

```text
配置文件在 Windows 本机：%UserProfile%\.wslconfig
影响范围：Windows Docker Desktop 使用的 WSL2 backend。
不影响：Rocky Linux 虚拟机里的 Docker Engine。
```

客户电脑内存较低时，Docker Desktop 不要无限占用内存。推荐使用项目模板：

```powershell
Copy-Item 'F:\跨境智汇AI知识库系统\ygh-deploy\host\wslconfig.template' "$HOME\.wslconfig" -Force
Get-Content "$HOME\.wslconfig"
wsl --shutdown
```

重新启动 Docker Desktop 后执行：

```powershell
docker info --format 'Docker memory: {{.MemTotal}} bytes'
```

项目模板当前限制 Docker Desktop/WSL2 使用约 3GB 内存、4 CPU、1GB Swap。若客户电脑内存大于 32GB，可由实施人员按实际情况调高，但必须保留变更记录。

## 第二步：配置 Rocky Linux 虚拟机

客户现在不要我们提供的虚拟机，因此虚拟机必须由客户自己从零配置。虚拟机配置不要看本节零散说明，直接打开独立文档执行：

```text
docs/deployment/Rocky Linux虚拟机从零配置指南.md
```

该文档从 VMware NAT 网络开始写，按“第一步、第二步、第三步”执行即可。下面“第二步-1”到“第二步-8”只保留为快速参考，正式交付以独立虚拟机指南为准。

### 第二步-1：建议配置

- CPU：2 核。
- 内存：3.5GB。
- 硬盘：至少 40GB，动态分配。
- 网络：VMware NAT，网段 `192.168.154.0/24`。
- 系统：Rocky Linux 9 x86_64 Minimal。

安装时创建普通用户 `wang`，并设置一个你能记住的密码。

### 第二步-2：下载虚拟化软件和 Rocky Linux

安装和文件位置：

```text
VMware Workstation Pro 安装到 Windows 本机。
默认安装路径示例：C:\Program Files (x86)\VMware\VMware Workstation
Rocky Linux ISO 只是安装镜像文件，建议保存到：D:\ISO\Rocky-9.x-x86_64-minimal.iso
Rocky Linux 系统最终安装到 VMware 虚拟机磁盘里，不安装到 Windows 本机目录。
```

推荐 VMware Workstation Pro。官方下载地址：

- VMware Workstation Pro：https://www.vmware.com/products/desktop-hypervisor/workstation-and-fusion
- Broadcom 支持下载入口：https://support.broadcom.com/
- Rocky Linux ISO：https://rockylinux.org/download

下载建议：

1. 下载并安装 VMware Workstation Pro for Windows。
2. 打开 https://rockylinux.org/download。
3. 选择 Rocky Linux 9。
4. 架构选择 `x86_64`。
5. 镜像选择 `Minimal ISO`，不需要下载 DVD 完整镜像。
6. 下载完成后保留 ISO 文件，示例：`D:\ISO\Rocky-9.x-x86_64-minimal.iso`。

### 第二步-3：导入我们交付的虚拟机

虚拟机位置：

```text
虚拟机文件放在 Windows 本机目录，例如：D:\VMs\ygh-rocky
Rocky Linux 运行在 VMware 虚拟机里。
虚拟机内部部署目录：/opt/ygh/constrained-dev
虚拟机内部 Docker 数据目录：/var/lib/docker
```

如果客户收到的是虚拟机压缩包，例如 `ygh-rocky-vm.zip`：

1. 解压到固定目录，例如 `D:\VMs\ygh-rocky`。
2. 打开 VMware Workstation Pro。
3. 点击 `File → Open`。
4. 选择解压目录中的 `.vmx` 文件。
5. 第一次启动时，如果 VMware 询问 `I moved it` 或 `I copied it`，选择 `I copied it`。
6. 登录虚拟机用户 `wang`。
7. 执行：

```bash
ip addr
docker version
docker compose version
cd /opt/ygh/constrained-dev
docker compose --env-file .env -f vm-compose.yml --profile core ps
```

如果 IP 已经是 `192.168.154.10`，可以直接跳到“第六步：配置虚拟机防火墙”；如果不是，按“第二步-6：将虚拟机设为固定 IP”重新设置固定 IP。

### 第二步-4：从零创建虚拟机

创建位置：

```text
VMware 虚拟机文件保存在 Windows 本机，例如：D:\VMs\ygh-rocky-dev
Rocky Linux 安装到该虚拟机的 40GB 虚拟硬盘里。
不是安装到 Windows 的 C 盘程序目录。
```

只有没有使用交付虚拟机时才执行本节：

1. VMware 点击 `Create a New Virtual Machine`。
2. 选择 `Typical`。
3. 选择下载好的 Rocky Linux Minimal ISO。
4. Guest OS 选择 `Linux`，版本选择 `Other Linux 5.x kernel 64-bit` 或 `Rocky Linux 64-bit`。
5. 虚拟机名称填写 `ygh-rocky-dev`。
6. 磁盘大小填写至少 `40GB`，选择 `Store virtual disk as a single file` 或 `Split` 均可。
7. 点击 `Customize Hardware`：
   - Memory：`3584MB`。
   - Processors：`2`。
   - Network Adapter：`NAT`。
8. 启动虚拟机，进入 Rocky 安装界面。
9. `Installation Destination` 选择默认自动分区。
10. `Root Password` 设置一个强密码。
11. `User Creation` 创建普通用户 `wang`，勾选允许管理员权限。
12. 安装完成后重启，登录 `wang`。

### 第二步-5：确认网卡名称

在虚拟机终端执行：

```bash
ip addr
nmcli connection show
```

常见网卡是 `ens160`。Linux 不使用 `ipconfig`，查 IP 使用 `ip addr`。

### 第二步-6：将虚拟机设为固定 IP

以下命令假设连接名为 `ens160`。如果 `nmcli connection show` 显示的名称不同，将命令中的 `ens160` 替换为实际名称。

```bash
sudo nmcli connection modify ens160 ipv4.method manual \
  ipv4.addresses 192.168.154.10/24 \
  ipv4.gateway 192.168.154.2 \
  ipv4.dns "223.5.5.5 8.8.8.8"
sudo nmcli connection up ens160
ip addr show ens160
```

预期看到 `inet 192.168.154.10/24`。如果 VMware NAT 网关不是 `192.168.154.2`，先在 Windows 执行 `ipconfig`，根据 VMware NAT 适配器配置调整。

在 Windows 验证：

```powershell
Test-NetConnection 192.168.154.10 -Port 22
```

预期 `TcpTestSucceeded : True`。

### 第二步-7：启用 SSH

```bash
sudo systemctl enable --now sshd
sudo systemctl status sshd --no-pager
```

预期包含 `Active: active (running)`。

在 Windows 测试：

```powershell
ssh wang@192.168.154.10
```

第一次连接输入 `yes`，再输入虚拟机用户密码。

### 第二步-8：配置 SSH 免密（推荐）

在 Windows PowerShell 执行：

```powershell
if (-not (Test-Path "$HOME\.ssh\id_ed25519")) { ssh-keygen -t ed25519 }
Get-Content "$HOME\.ssh\id_ed25519.pub" | ssh wang@192.168.154.10 `
  'umask 077; mkdir -p ~/.ssh; cat >> ~/.ssh/authorized_keys; chmod 600 ~/.ssh/authorized_keys'
ssh -o BatchMode=yes wang@192.168.154.10 'echo SSH_OK'
```

生成密钥时可以一直按回车使用默认值。最后预期输出 `SSH_OK`。若出现 `Permission denied`，在虚拟机执行：

```bash
chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys
restorecon -RFv ~/.ssh
sudo systemctl restart sshd
```

## 第四步：手动生成脱离 Git 的密钥配置

配置文件位置：

```text
在 Windows 本机项目目录生成：F:\跨境智汇AI知识库系统\ygh-deploy\constrained-dev\.env
随后复制到虚拟机：/opt/ygh/constrained-dev/.env
这个文件不是 Docker 镜像，不放到 Git，不上传到 GitHub。
```

进入部署目录：


## 第十二步：配置豆包 AI

没有 API Key 时，AI 服务会“失败关闭”：不伪造模型回答，返回 `MODEL_NOT_CONFIGURED`。这不影响商城、知识库和培训系统开发。

获得豆包 Key 和模型 Endpoint ID 后，只在本地 `.env` 追加：

```powershell
Add-Content .env 'YGH_DOUBAO_API_KEY=在这里粘贴真实Key'

Add-Content .env 'YGH_DOUBAO_EMBEDDING_MODEL=在这里填向量Endpoint-ID'
```

不要把真实 Key 写入 `application.yml`、Markdown 或 GitHub。配置后重建 `search` 和 `ai` 容器。

## 第十六步：常见故障处理

### 第十六步-1：`ipconfig: command not found`

你正在 Linux 中。请用：

```bash
ip addr
```

### 第十六步-2：Docker Desktop 提示 WSL integration unexpectedly stopped

1. 点“Skip WSL distro integration”，不要反复强制重启。
2. 退出 Docker Desktop。
3. 管理员 PowerShell 执行：

```powershell
wsl --shutdown
wsl --update
wsl -d Ubuntu --exec true
docker desktop start
```

4. 等 Docker Desktop 显示 Engine running，再重新打开 Ubuntu integration。

### 第十六步-3：虚拟机 SSH `Permission denied`

先确认密码登录是否可用，再按“第二步-5：确认网卡名称”和“第二步-8：配置 SSH 免密”修复 `.ssh` 权限和 SELinux 标签。不要通过关闭 SSH 密钥校验或 SELinux 规避问题。

### 第十六步-4：`port is already allocated`

```powershell
Get-NetTCPConnection -State Listen | Where-Object LocalPort -In 8080,8091,19876,19200
docker ps --format 'table {{.Names}}\t{{.Ports}}'
```

先停止占用端口的无关开发服务，不要随意修改企业约定端口。

### 第十六步-5：容器一直 `unhealthy`

```powershell
docker inspect --format '{{json .State.Health}}' 容器名
docker logs --tail 200 容器名
```

常见原因是虚拟机组件未启动、`.env` 缺失、防火墙未放行、Docker 内存不足或 Nacos 仍在启动。

### 第十六步-6：Maven 构建失败

```powershell
java -version
.\mvnw.cmd --version
docker version
```

必须为 Java 25，Docker Engine 必须正常。不要删除失败测试或降低断言来“让构建变绿”。

## 第十七步：备份和恢复

在虚拟机手动执行备份：

```bash
cd /opt/ygh/constrained-dev
backup_dir="/opt/ygh/backups/$(date +%Y%m%d-%H%M%S)"
mkdir -p "$backup_dir"
docker compose --env-file .env -f vm-compose.yml --profile core exec -T mysql sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysqldump -uroot --all-databases --single-transaction --routines --events' | gzip > "$backup_dir/mysql-all.sql.gz"
docker compose --env-file .env -f vm-compose.yml --profile ai-data exec -T pgvector pg_dump -U ygh_vector -d ygh_vector | gzip > "$backup_dir/pgvector-ygh-vector.sql.gz"
cd "$backup_dir"
sha256sum * > SHA256SUMS.txt
ls -lh
```

预期看到 `mysql-all.sql.gz`、`pgvector-ygh-vector.sql.gz` 和 `SHA256SUMS.txt`。如果没有启动 PGVector，可以跳过 `pg_dump` 那一行。

恢复是破坏性操作，不在本教程中让客户复制脚本直接执行。恢复前必须先确认备份时间、停写入流量、保留当前数据卷快照，再按《备份恢复与索引重建手册》逐项恢复 MySQL、PGVector 和索引。

恢复后必须重新执行本教程的端口检查、组件健康检查和第一次功能验收。

## 第十八步：生产服务器部署说明

`ygh-deploy/enterprise-server/compose.yml` 是企业全量编排基线，包含两个前端、14 个 Java 服务、MySQL、Redis、Nacos、RocketMQ、Seata、PGVector、Elasticsearch、Prometheus、Alertmanager、Grafana 等。

它不适合当前 3.5GB 虚拟机全量常驻。生产建议：

- 至少 16 核 CPU、32GB 内存和 200GB SSD 作为单机验收起点，真实容量以压测结果为准。
- MySQL、Redis、Nacos、RocketMQ、Elasticsearch 使用高可用集群或云托管服务。
- 镜像必须使用不可变版本或 digest，不用 `latest`。
- Secret 由部署平台注入，不将真实 `.env` 传到服务器 Git 目录。
- 对外只开放 HTTPS 443；数据库、Redis、Nacos、RocketMQ 仅开放给内网服务。

部署前校验：

```bash
cd ygh-deploy/enterprise-server
cp .env.example .env
# 使用 Secret 管理系统填充 .env，不要将文件提交到 Git
docker compose --env-file .env config >/dev/null
docker compose --env-file .env pull
docker compose --env-file .env up -d
```

部署后手动执行 MySQL、Redis、Nacos、PGVector、网关 readiness 和前端访问检查，通过后才切换流量。回滚使用上一个已验证的不可变版本，不要就地修改正在运行的容器。
