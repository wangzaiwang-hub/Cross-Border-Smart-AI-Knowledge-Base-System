# 跨境智汇 AI 系统：从零开始完整部署教程

> 适用版本：JDK 25、Spring Boot 4.0.7、Vue 3。  
> 适用环境：Windows 11 开发机 + Rocky Linux 虚拟机 + Docker。  
> 面向读者：没有 Linux、Docker 或 Java 项目经验的初学者。

## 1. 先了解最终会得到什么

部署完成后，系统分布如下：

| 位置 | 长期运行 | 按需运行 |
|---|---|---|
| Rocky Linux 虚拟机 `192.168.154.10` | MySQL 8.4.10、Redis 8.4.4、Nacos 3.1.1 | PostgreSQL 17 + PGVector 0.8.5 |
| Windows Docker Desktop | 无 | RocketMQ 5.3.1 + Seata 2.5.0，或 Elasticsearch 8.19.17 |
| Windows | Git、JDK 25、Maven Wrapper、Node.js/pnpm | 14 个 Java 服务、商城前端、管理前端 |

这是针对当前低配置电脑的开发方案。RocketMQ/Seata 和 Elasticsearch 不同时启动，Java 服务也按业务场景分批启动。

## 2. 操作前的安全规则

1. 看到命令块时，只复制命令内容，不复制行首的说明文字。
2. PowerShell 命令在 Windows Terminal 的“PowerShell”页签执行；Linux 命令在虚拟机终端执行。
3. 不要执行 `docker compose down -v`；`-v` 会删除数据卷。
4. 不要把 `.env`、Token、API Key 或密码截图发给别人。
5. 本教程使用项目自动生成的随机密码，不使用 `123456`。

## 3. 准备 Windows

### 3.1 确认 Windows 版本和内存

按 `Win + R`，输入 `winver`，按回车。建议使用 Windows 11 22H2 或更新版本。

打开 PowerShell，执行：

```powershell
Get-ComputerInfo | Select-Object WindowsProductName,WindowsVersion,OsTotalVisibleMemorySize
```

预期看到 Windows 名称、版本号和内存数字。当前方案按约 15GB 物理内存设计。

### 3.2 安装 Git

以管理员身份打开 PowerShell：

```powershell
winget install --id Git.Git -e --source winget
git --version
```

预期输出类似 `git version 2.x.x.windows.x`。如果第二条命令提示找不到，关闭当前 PowerShell 后重新打开。

### 3.3 安装 JDK 25

```powershell
winget search Temurin 25
winget install --id EclipseAdoptium.Temurin.25.JDK -e
java -version
```

预期第一行包含 `openjdk version "25` 。项目实测版本为 25.0.3。

如果 `java -version` 仍显示旧版本：

```powershell
Get-ChildItem 'C:\Program Files\Eclipse Adoptium' -Directory
```

在“系统属性 → 高级 → 环境变量”中将 `JAVA_HOME` 设为列出的 JDK 25 目录，并把 `%JAVA_HOME%\bin` 放到 `Path` 前部。

### 3.4 安装 Node.js 和 pnpm

```powershell
winget install --id OpenJS.NodeJS.LTS -e
node --version
corepack enable
corepack prepare pnpm@10.13.1 --activate
pnpm --version
```

预期 `pnpm --version` 输出 `10.13.1`。

### 3.5 安装 WSL2 Ubuntu

以管理员身份执行：

```powershell
wsl --install -d Ubuntu
```

安装结束后重启电脑。第一次打开 Ubuntu 时，按提示输入 Linux 用户名和密码。输入密码时屏幕不显示字符是正常现象。

验证：

```powershell
wsl --status
wsl --list --verbose
```

预期 Ubuntu 的 `VERSION` 为 `2`。

### 3.6 安装 Docker Desktop

```powershell
winget install --id Docker.DockerDesktop -e
```

重启 Windows，打开 Docker Desktop，第一次使用时：

1. 接受许可协议。
2. Settings → General，勾选“Use the WSL 2 based engine”。
3. Settings → Resources → WSL Integration，打开 Ubuntu。
4. 本机低配模式使用项目已配置的 3GB 上限；如需重新配置，先备份 `%UserProfile%\.wslconfig`，再参考 `ygh-deploy/host/wslconfig.template`。

验证：

```powershell
docker version
docker info --format 'Docker memory: {{.MemTotal}} bytes'
docker run --rm hello-world
```

预期最后一条命令显示 `Hello from Docker!`。

> 不要在 Docker Desktop 运行期间执行 `wsl --terminate Ubuntu`。如必须重启 WSL，依次执行 `docker desktop stop`、`wsl --shutdown`、`wsl -d Ubuntu --exec true`、`docker desktop start`。

## 4. 创建 Rocky Linux 虚拟机

### 4.1 建议配置

- CPU：2 核。
- 内存：3.5GB。
- 硬盘：至少 40GB，动态分配。
- 网络：VMware NAT，网段 `192.168.154.0/24`。
- 系统：Rocky Linux 9 x86_64 Minimal。

安装时创建普通用户 `wang`，并设置一个你能记住的密码。

### 4.2 确认网卡名称

在虚拟机终端执行：

```bash
ip addr
nmcli connection show
```

常见网卡是 `ens160`。Linux 不使用 `ipconfig`，查 IP 使用 `ip addr`。

### 4.3 将虚拟机设为固定 IP

以下命令假设连接名为 `ens160`。如果 `nmcli connection show` 显示的名称不同，将命令中的 `ens160` 替换为实际名称。

```bash
sudo nmcli connection modify ens160 ipv4.method manual \
  ipv4.addresses 192.168.154.10/24 \
  ipv4.gateway 192.168.154.2 \
  ipv4.dns "223.5.5.5 8.8.8.8"
sudo nmcli connection up ens160
ip addr show ens160
```

预期看到 `inet 192.168.154.10/24`。如果 VMware NAT 网关不是 `192.168.154.2`，先在 Windows 执行 `ipconfig`，根据 VMware NAT 适配器配置调整。

在 Windows 验证：

```powershell
Test-NetConnection 192.168.154.10 -Port 22
```

预期 `TcpTestSucceeded : True`。

### 4.4 启用 SSH

```bash
sudo systemctl enable --now sshd
sudo systemctl status sshd --no-pager
```

预期包含 `Active: active (running)`。

在 Windows 测试：

```powershell
ssh wang@192.168.154.10
```

第一次连接输入 `yes`，再输入虚拟机用户密码。

### 4.5 配置 SSH 免密（推荐）

在 Windows PowerShell 执行：

```powershell
if (-not (Test-Path "$HOME\.ssh\id_ed25519")) { ssh-keygen -t ed25519 }
Get-Content "$HOME\.ssh\id_ed25519.pub" | ssh wang@192.168.154.10 `
  'umask 077; mkdir -p ~/.ssh; cat >> ~/.ssh/authorized_keys; chmod 600 ~/.ssh/authorized_keys'
ssh -o BatchMode=yes wang@192.168.154.10 'echo SSH_OK'
```

生成密钥时可以一直按回车使用默认值。最后预期输出 `SSH_OK`。若出现 `Permission denied`，在虚拟机执行：

```bash
chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys
restorecon -RFv ~/.ssh
sudo systemctl restart sshd
```

## 13. 启动 Java 服务

服务分为四组：

| Profile | 服务 |
|---|---|
| `platform` | Gateway、Auth、User、System、Admin |
| `mall` | Product、Inventory、Order、Wallet、Notification |
| `ai-apps` | Knowledge、Search、AI |
| `training` | Training |

低配机不建议一次启动全部。先启动平台：

```powershell
Set-Location 'F:\跨境智汇AI知识库系统\ygh-deploy\constrained-dev'
.\scripts\apps-profile.ps1 -Profile platform -Action up
.\scripts\apps-profile.ps1 -Profile platform -Action status
```

脚本会先构建 Maven 包，再构建 Docker 镜像。第一次可能耗时较长。预期 Gateway 映射到 Windows `8080`，各服务最终为 `healthy`。

验证网关：

```powershell
Invoke-RestMethod http://localhost:8080/actuator/health/readiness
Invoke-RestMethod http://localhost:8080/api/v1/auth/captcha
```

第一条预期 `status` 为 `UP`；第二条预期返回统一的 `code/message/data/traceId/timestamp`。

切换业务服务时，建议保留 `platform`，每次只启动一个业务 Profile。例如商城：

```powershell
.\scripts\local-profile.ps1 -Mode mall-deps
.\scripts\apps-profile.ps1 -Profile mall -Action up
```

AI：

```powershell
.\scripts\local-profile.ps1 -Mode stop
.\scripts\local-profile.ps1 -Mode ai-deps
.\scripts\apps-profile.ps1 -Profile ai-apps -Action up
```

停止某组 Java 服务时使用精确服务名，避免将同一 Compose 项目的 Gateway 一起停掉。例如停止商城服务：

```powershell
docker compose --env-file .env -f apps-compose.yml stop product inventory order wallet notification
```

`stop` 不会删除容器和数据卷。只在希望停掉该 Compose 项目的所有 Java 服务时，才使用 `apps-profile.ps1 -Action down`。

## 14. 配置豆包 AI

没有 API Key 时，AI 服务会“失败关闭”：不伪造模型回答，返回 `MODEL_NOT_CONFIGURED`。这不影响商城、知识库和培训系统开发。

获得豆包 Key 和模型 Endpoint ID 后，只在本地 `.env` 追加：

```powershell
Add-Content .env 'YGH_DOUBAO_API_KEY=在这里粘贴真实Key'
Add-Content .env 'YGH_DOUBAO_CHAT_MODEL=在这里填聊天Endpoint-ID'
Add-Content .env 'YGH_DOUBAO_EMBEDDING_MODEL=在这里填向量Endpoint-ID'
```

不要把真实 Key 写入 `application.yml`、Markdown 或 GitHub。配置后重建 `search` 和 `ai` 容器。

## 18. 常见故障处理

### 18.1 `ipconfig: command not found`

你正在 Linux 中。请用：

```bash
ip addr
```

### 18.2 Docker Desktop 提示 WSL integration unexpectedly stopped

1. 点“Skip WSL distro integration”，不要反复强制重启。
2. 退出 Docker Desktop。
3. 管理员 PowerShell 执行：

```powershell
wsl --shutdown
wsl --update
wsl -d Ubuntu --exec true
docker desktop start
```

4. 等 Docker Desktop 显示 Engine running，再重新打开 Ubuntu integration。

### 18.3 虚拟机 SSH `Permission denied`

先确认密码登录是否可用，再按第 4.5 节修复 `.ssh` 权限和 SELinux 标签。不要通过关闭 SSH 密钥校验或 SELinux 规避问题。

### 18.4 `port is already allocated`

```powershell
Get-NetTCPConnection -State Listen | Where-Object LocalPort -In 8080,8091,19876,19200
docker ps --format 'table {{.Names}}\t{{.Ports}}'
```

先停止占用端口的无关开发服务，不要随意修改企业约定端口。

### 18.5 容器一直 `unhealthy`

```powershell
docker inspect --format '{{json .State.Health}}' 容器名
docker logs --tail 200 容器名
```

常见原因是虚拟机组件未启动、`.env` 缺失、防火墙未放行、Docker 内存不足或 Nacos 仍在启动。

### 18.6 Maven 构建失败

```powershell
java -version
.\mvnw.cmd --version
docker version
```

必须为 Java 25，Docker Engine 必须正常。不要删除失败测试或降低断言来“让构建变绿”。

## 19. 备份和恢复

在虚拟机执行备份：

```bash
cd /opt/ygh/constrained-dev
./scripts/backup-data.sh
```

预期输出 `BACKUP_OK path=/opt/ygh/backups/...`。备份包含 MySQL、正在运行时的 PGVector 和知识附件，并生成 SHA-256 校验。

```bash
./scripts/restore-data.sh /opt/ygh/backups/具体时间目录 --confirm
```

预期先看到每个文件 `OK`，最后看到 `RESTORE_OK`。恢复后按《备份恢复与索引重建手册》重建 Elasticsearch/PGVector 索引并做全链路冒烟测试。

## 20. 生产服务器部署说明

`ygh-deploy/enterprise-server/compose.yml` 是企业全量编排基线，包含两个前端、14 个 Java 服务、MySQL、Redis、Nacos、RocketMQ、Seata、PGVector、Elasticsearch、Prometheus、Alertmanager、Grafana 等。

它不适合当前 3.5GB 虚拟机全量常驻。生产建议：

- 至少 16 核 CPU、32GB 内存和 200GB SSD 作为单机验收起点，真实容量以压测结果为准。
- MySQL、Redis、Nacos、RocketMQ、Elasticsearch 使用高可用集群或云托管服务。
- 镜像必须使用不可变版本或 digest，不用 `latest`。
- Secret 由部署平台注入，不将真实 `.env` 传到服务器 Git 目录。
- 对外只开放 HTTPS 443；数据库、Redis、Nacos、RocketMQ 仅开放给内网服务。

部署前校验：

```bash
cd ygh-deploy/enterprise-server
cp .env.example .env
# 使用 Secret 管理系统填充 .env，不要将文件提交到 Git
docker compose --env-file .env config >/dev/null
docker compose --env-file .env pull
docker compose --env-file .env up -d
```

部署后执行 `health-check.ps1` 或同等健康检查，通过后才切换流量。回滚使用上一个已验证的不可变版本，不要就地修改正在运行的容器。
